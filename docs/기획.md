# 웹페이지 작성 기록 아카이버

> 현재 열려 있는 웹페이지의 화면 내용과 작성 중인 입력값을 함께 읽어, 검토 가능한 마크다운 기록으로 남기는 크롬 확장 프로그램.

## 1. 기획 배경

채용 지원서를 작성할 때 이력서 정보, 경력, 프로젝트, 자기소개서 답변은 여러 입력칸에 흩어져 있다. 기업마다 채용 시스템(ATS)의 화면과 항목이 다르고, 제출 후에는 실제로 어떤 질문에 무슨 답변을 냈는지 다시 확인하기 어려울 수 있다.

사용자가 지원 과정에서 작성하고 확인한 내용을 **사용자 자신의 파일로 보관**할 수 있게 한다. 채용 지원서가 첫 사용처이지만, 특정 ATS에만 묶이지 않는 범용 페이지 저장 도구로 시작한다.

## 2. 제품 목표

사용자가 확장 프로그램을 누른 순간의 **현재 페이지 내용과 입력 상태**를 읽고, 누락 여부를 확인한 다음 `.md` 파일로 저장한다.

핵심 원칙은 다음과 같다.

- **원문 보존:** 작성한 답변을 요약하거나 다시 쓰지 않고 그대로 남긴다.
- **명시적 실행:** 사용자가 현재 페이지에서 저장을 요청할 때 읽는다.
- **저장 전 검토:** 추출 결과를 미리 보고 불필요한 내용은 제외할 수 있다.
- **범용 기능 우선:** 기본 추출을 만든 뒤 실제로 누락이 발생하는 ATS부터 보완한다.
- **로컬 우선:** 첫 버전에는 계정이나 서버 없이 파일을 다운로드한다.

## 3. 주요 사용 시점

목적은 **제출한 내용(제출본)을 내 파일로 남기는 것** 하나다. 제출 전후를 나눠 기록하지 않는다.

- **제출 후 보기 화면이 있는 사이트:** 접수 완료·지원 내역·지원서 보기 화면에서 저장한다. 실제로 제출된 내용이므로 가장 정확하다.
- **제출 후 답변을 볼 수 없는 사이트:** 제출 직전 작성 화면에서 저장해 둔다. 이 기록은 제출 버튼을 누르기 직전의 상태다.

기록에는 어떤 화면에서 읽었는지(작성 화면 / 보기 화면)를 자동으로 적는다. 사용자가 고르지 않는다.

## 4. 첫 버전의 사용자 흐름

1. 저장할 웹페이지를 연다.
2. 크롬 확장 프로그램 아이콘을 누른다.
3. 추출된 페이지 내용과 입력값을 미리 본다.
4. 빠진 내용이나 불필요한 내용을 확인하고 필요하면 제외한다.
5. 마크다운 파일을 다운로드한다.

첫 버전은 **현재 탭의 현재 페이지 한 장**을 대상으로 한다. 제출 버튼을 누르거나 페이지의 입력값을 변경하지 않는다.

## 5. 수집 대상

| 구분          | 예시                                   | 기록 방식                                                 |
| ------------- | -------------------------------------- | --------------------------------------------------------- |
| 화면 내용     | 공고명, 질문 제목, 안내 문구, 표       | 가능한 한 제목·문단·표 구조를 유지                        |
| 텍스트 입력값 | 이름, 학교, 경력 설명, 자기소개서 답변 | 항목명과 현재 값을 짝지어 기록                            |
| 선택값        | 드롭다운, 라디오 버튼, 체크박스        | 선택된 항목을 기록                                        |
| 반복 항목     | 경력 1·2, 프로젝트 1·2                 | 화면 순서와 묶음을 유지                                   |
| 페이지 정보   | 제목, URL, 저장 시각, 읽은 화면        | 기록의 상단에 표시                                        |
| 첨부파일      | 이력서 PDF, 증명서                     | 파일 자체는 담지 않고, 파일 이름이나 첨부 여부(📎)만 기록 |

비밀번호, 일회용 인증번호 등 지원 내용과 무관한 민감 입력칸은 저장 대상에서 제외한다.

일반적인 웹페이지 마크다운 변환은 화면 본문에 초점을 맞추므로 작성 중인 입력칸의 **현재 값**을 놓칠 수 있다. 이 제품은 화면 내용과 현재 입력 상태를 함께 다루는 것이 핵심이다.

## 6. 결과물 예시

```markdown
# 지원서 작성 기록

- 페이지: ○○기업 신입 개발자 지원
- URL: https://example.com/apply/123
- 저장 시각: 2026-11-24 21:30
- 읽은 화면: 작성 화면 (입력칸 23개)

## 기본 정보

### 이름

김○○

### 이메일

example@email.com

## 경력

### 경력 1 — 회사명

○○회사

### 경력 1 — 담당 업무

...

## 자기소개서

### 지원 동기

_글자 수: 공백 포함 812자 · 공백 제외 623자 · 제한 1,000자_

제가 이 직무에 지원한 이유는...

### 문제 해결 경험

...
```

마크다운의 꾸밈보다 **질문과 답변의 정확한 연결, 원문 보존, 누락 확인**을 우선한다.

## 7. ATS 대응 방식

처음에는 페이지 유형에 관계없이 동작하는 기본 추출 방식을 만든다. 실제 사용 중 특정 ATS의 특수 에디터, 반복 항목, 접힌 영역에서 누락이나 순서 오류가 확인되면 해당 ATS에 맞는 처리를 추가한다.

URL의 도메인과 경로는 ATS를 **추정하는 단서**로 사용할 수 있다. 회사 자체 도메인이나 화면 내 삽입 형태도 있으므로 URL만으로 확정하지 않는다. 기록에는 원본 URL을 함께 남긴다.

## 8. 단계별 개발 계획

### 1단계 — 현재 페이지 한 장 저장

- 화면 내용과 일반적인 입력값을 읽는다.
- 추출 미리보기와 `.md` 다운로드를 제공한다.
- 가짜 지원 페이지와 실제 ATS 한 곳의 단일 페이지에서 결과를 확인한다.

### 2단계 — 누락되는 입력 형태 보완

- 반복 경력 항목, 특수 자소서 에디터, 접힌 영역 등 실제 사례를 보완한다.
- 발견한 누락 사례를 재현 가능한 검증 자료로 남긴다.

### 3단계 — 지원 기록으로 묶기

- 한 지원서가 여러 화면(탭·URL)에 나뉘어 있거나, 같은 지원 건을 여러 번 저장한 경우를 같은 지원 건으로 묶는다.
- 회사·직무·지원일·이력서 버전으로 찾을 수 있게 한다.

### 4단계 — 작성 보조

- (글자 수 기록은 1단계에서 먼저 넣었다: 답변마다 공백 포함·제외 글자 수와 제한을 적는다.)
- 과거 답변을 검색하고 비슷한 자소서 질문을 찾는다.
- 필요하면 Qwen 같은 모델을 분류·검색·정리에 사용한다. 모델의 결과가 저장된 원문을 대체하지 않도록 한다.

## 9. 개발과 검증

첫 버전에는 긴 텍스트 답변, 빈 입력칸, 체크박스, 라디오 버튼, 드롭다운, 반복 항목이 있는 **시험 페이지**를 준비한다. 예상한 내용이 마크다운에 정확히 남는지 검사한다.

프로젝트의 하네스에는 기능의 완료 조건, 시험 페이지, 예상 결과, 실제 ATS에서 발견한 누락 사례를 기록한다. 검사가 준비된 뒤에는 Husky를 연결해 커밋 전에 빠른 검사를 자동 실행할 수 있다. 실제 ATS의 결과는 추출 미리보기와 원본 화면을 직접 대조한다.

## 10. 첫 버전의 완료 기준

- 현재 페이지에서 확장 프로그램을 실행할 수 있다.
- 화면의 주요 내용과 일반적인 입력값·선택값이 항목명과 함께 추출된다.
- 추출 결과를 저장 전에 확인할 수 있다.
- 원문을 유지한 마크다운 파일을 다운로드할 수 있다.
- 시험 페이지와 실제 단일 페이지 ATS 한 곳에서 누락 여부를 확인한다.
