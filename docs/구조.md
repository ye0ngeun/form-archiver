# 구조 설명

## 크롬 확장이 동작하는 방식

크롬 확장은 몇 개의 독립된 조각으로 이뤄진다.

| 조각                   | 이 프로젝트에서           | 하는 일                                                            |
| ---------------------- | ------------------------- | ------------------------------------------------------------------ |
| manifest               | `wxt.config.ts` 에서 생성 | 확장의 이름, 권한, 아이콘을 누르면 열릴 화면을 크롬에 알려준다     |
| 팝업                   | `entrypoints/popup/`      | 아이콘을 누르면 뜨는 작은 창. 미리보기와 다운로드 버튼이 여기 있다 |
| 페이지에 주입하는 코드 | (작성 예정)               | 사용자가 보고 있는 탭 안에서 실행되어 화면 내용과 입력값을 읽는다  |

팝업은 웹페이지 안쪽을 직접 볼 수 없다. 그래서 팝업이 `scripting` 권한으로
"읽기 코드"를 현재 탭에 한 번 실행시키고, 그 결과만 돌려받는다.

## WXT가 대신 해주는 일

WXT는 크롬 확장 전용 빌드 도구다. 없으면 직접 해야 하는 일을 맡는다.

- **manifest.json 생성:** `wxt.config.ts` 와 `entrypoints/` 폴더 구성을 보고 만든다.
  결과물은 `npm run build` 후 `.output/chrome-mv3/manifest.json` 에서 볼 수 있다.
- **TypeScript 변환과 묶기:** 크롬은 TypeScript를 모르므로 JS로 바꿔 묶는다(내부적으로 Vite 사용).
- **개발 중 자동 새로고침:** `npm run dev` 는 확장을 올린 크롬을 띄우고, 코드를 고치면 다시 불러온다.
- **타입 정보 준비:** `npm install` 후 `wxt prepare` 가 `.wxt/` 폴더에 설정과 타입을 만든다.
  `tsconfig.json` 은 이를 이어받기만 한다.
- **배포 파일:** `npm run zip` 으로 웹스토어에 올릴 zip을 만든다.

`.output/` 과 `.wxt/` 는 자동 생성물이라 git에 올리지 않는다.
