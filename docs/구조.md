# 구조 설명

## 크롬 확장이 동작하는 방식

크롬 확장은 몇 개의 독립된 조각으로 이뤄진다.

| 조각                   | 이 프로젝트에서           | 하는 일                                                            |
| ---------------------- | ------------------------- | ------------------------------------------------------------------ |
| manifest               | `wxt.config.ts` 에서 생성 | 확장의 이름, 권한, 아이콘을 누르면 열릴 화면을 크롬에 알려준다     |
| 팝업                   | `entrypoints/popup/`      | 아이콘을 누르면 뜨는 작은 창. 미리보기와 다운로드 버튼이 여기 있다 |
| 페이지에 주입하는 코드 | (작성 예정)               | 사용자가 보고 있는 탭 안에서 실행되어 화면 내용과 입력값을 읽는다  |

팝업은 웹페이지 안쪽을 직접 볼 수 없다. 그래서 팝업이 `scripting` 권한으로
"읽기 코드"를 현재 탭에 한 번 실행시키고, 그 결과만 돌려받는다.

## WXT가 대신 해주는 일

WXT는 크롬 확장 전용 빌드 도구다. 없으면 직접 해야 하는 일을 맡는다.

- **manifest.json 생성:** `wxt.config.ts` 와 `entrypoints/` 폴더 구성을 보고 만든다.
  결과물은 `npm run build` 후 `.output/chrome-mv3/manifest.json` 에서 볼 수 있다.
- **TypeScript 변환과 묶기:** 크롬은 TypeScript를 모르므로 JS로 바꿔 묶는다(내부적으로 Vite 사용).
- **개발 중 자동 새로고침:** `npm run dev` 는 확장을 올린 크롬을 띄우고, 코드를 고치면 다시 불러온다.
- **타입 정보 준비:** `npm install` 후 `wxt prepare` 가 `.wxt/` 폴더에 설정과 타입을 만든다.
  `tsconfig.json` 은 이를 이어받기만 한다.
- **배포 파일:** `npm run zip` 으로 웹스토어에 올릴 zip을 만든다.

`.output/` 과 `.wxt/` 는 자동 생성물이라 git에 올리지 않는다.

## 추출기가 페이지를 읽는 방식 (`lib/extract-page.ts`)

페이지를 위에서 아래로 한 번 훑으며 "블록" 목록을 만든다.

| 블록            | 무엇                                               |
| --------------- | -------------------------------------------------- |
| `heading`       | 제목(h1~h6)                                        |
| `text`          | 문단                                               |
| `list`, `table` | 목록, 표                                           |
| `field`         | 입력칸 하나 (항목명 + 현재 값)                     |
| `skipped`       | 민감해서 값을 읽지 않은 입력칸 (미리보기에만 보임) |

### 입력칸의 항목명을 찾는 순서

1. `<label>` 로 연결된 글자
2. `aria-label` / `aria-labelledby`
3. 라디오·체크박스 묶음이면 `<fieldset>` 의 `<legend>`
4. **바로 앞 짧은 문단** — ATS 에서 흔한 `<div>질문</div><textarea>` 형태. 짐작이다.
5. **바로 앞 제목** — 제목은 그대로 두고 항목명으로만 쓴다.
6. `placeholder`, 그다음 `name` 속성 — 짐작이다.

4·6번처럼 짐작한 항목명은 `labelSource` 에 표시되어, 미리보기에서 확인을 권할 수 있다.

### 읽지 않는 것

- 비밀번호, 인증번호(OTP), 카드번호처럼 보이는 칸의 값
- `hidden` 입력칸, 화면에서 숨겨진 영역(`display: none` 등)
- 다른 출처의 iframe 안 내용

### 왜 함수 하나에 모든 걸 넣었나

팝업은 `chrome.scripting.executeScript({ func: extractPage })` 로 이 함수를 탭 안에서 실행한다.
크롬은 함수의 **소스 글자만** 탭으로 옮기기 때문에, 함수 밖에 있는 도우미를 부를 수 없다.
그래서 도우미 함수를 모두 `extractPage` 안에 두었고, 검사(`tests/extract-page.test.ts` 마지막)에서
소스 글자만으로 실행되는지 확인한다.

## 마크다운 규칙 (`lib/markdown.ts`)

- 문서 제목은 `#`, 페이지의 h1 은 `##` 부터 시작한다.
- 입력칸 항목명은 그 위 제목보다 한 단계 아래 제목으로 쓰고, 값은 바로 아래에 둔다.
- 라디오·체크박스는 모든 선택지를 `- [x]` / `- [ ]` 로 보여준다.
- 빈칸은 `_(비어 있음)_` 으로 표시한다.
- 답변 원문 줄 첫머리의 `#`, `-`, `>`, `1.` 같은 기호 앞에는 `\` 를 붙인다.
  마크다운으로 볼 때 원문과 똑같이 보이게 하기 위해서다(제목·목록으로 바뀌지 않음).

## 팝업이 동작하는 순서

1. 아이콘을 누르면 `entrypoints/popup/main.ts` 가 현재 탭을 찾는다.
2. `chrome://` 나 웹스토어처럼 크롬이 막는 주소면 안내 문구를 보여준다.
3. `scripting.executeScript({ func: extractPage })` 로 그 탭에서 추출기를 한 번 실행하고 결과(JSON)만 받는다.
4. `view.ts` 가 결과를 그린다. 체크를 해제한 블록 id 는 `excluded` 에 모이고, 마크다운 변환 때 빠진다.
5. **마크다운 저장**은 글자를 Blob 으로 만들어 `<a download>` 로 내려받는다. 그래서 `downloads` 권한이 필요 없다.

페이지에서 읽은 글자는 팝업에 `textContent` 로만 넣는다. `innerHTML` 을 쓰면 지원서 페이지의 글자가
팝업 안에서 HTML 로 실행될 수 있기 때문이다.
