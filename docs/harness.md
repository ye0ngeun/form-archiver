# 하네스: 완료 조건 · 시험 페이지 · 누락 사례

기능이 "됐다"고 말하기 위한 기준과 그 근거를 이 파일에 모은다.

## 1단계 완료 조건

- [x] 현재 페이지에서 확장 프로그램을 실행할 수 있다. (2026-11-24 실제 크롬·인크루트에서 확인)
- [x] 화면의 주요 내용과 일반적인 입력값·선택값이 항목명과 함께 추출된다. (시험 페이지 통과, 인크루트 제출 후 화면 확인. 실제 ATS 의 **작성 중 화면**(입력칸)은 확인 전)
- [x] 추출 결과를 저장 전에 확인하고, 항목을 제외할 수 있다. (팝업 미리보기 페이지에서 확인)
- [x] 마크다운 파일을 다운로드할 수 있다. (2026-11-24 실제 크롬에서 확인)
- [x] 원문을 유지한다. (2026-11-24 인크루트 제출 후 화면에서 자기소개서 4문항의 문단이 화면과 같음을 확인)
- [x] 비밀번호·인증번호 칸의 값은 읽지 않는다. (시험 페이지 검사)
- [x] 시험 페이지의 자동 검사가 통과한다.
- [x] 인크루트 지원서 한 화면에서 원본과 대조해 누락 여부를 확인한다. (2026-11-24 제출 후 보기 화면: 1차 대조에서 5건 발견 → 고친 뒤 재대조에서 모두 해결 확인)

## 1단계 범위에서 하지 않는 것

- 여러 화면으로 나뉜 단계형 지원서
- 첨부파일 내용 저장 (파일 이름만 기록)
- 다른 출처의 iframe 안 내용

검사 코드: `tests/extract-page.test.ts`, `tests/incruit-view.test.ts`, `tests/markdown.test.ts`, `tests/preview.test.ts` (`npm test`)

팝업 화면은 `npm run preview:popup` 으로 시험 페이지와 나란히 띄워 눈으로 확인한다.

예상 결과 파일(`*.expected.md`)은 검사가 처음 실행될 때 만들어진다. 추출 방식을 바꿔 결과가 달라지면 검사가 실패한다.
달라진 결과가 맞다면 `npx vitest run -u` 로 예상 파일을 갱신하고, **바뀐 부분을 사람이 직접 읽고** 커밋한다.
